# AIDR 证据查询与审计追赶：100 客户端混合负载复测

本轮完成低、高负载各三组成对对照，共 12 轮。审计追赶改善在六组中重复出现，但高负载采集吞吐未提升，窗口末积压略增，页面尾延迟也没有稳定改善。模型网关 P95 中位值下降，但两种负载均有一组升高，低负载波动扩大；因此不能确认“没有影响网关 P95”，整体性能验收尚未通过。

本轮仅执行测试和整理报告。数据库保持 SQLite，未修改应用代码、提交、推送或部署。

## 基线与测试条件

分支 `RENA-1470`，HEAD `eeee22bc312991b64d4c54c8da4fb30c2596a925`，工作区包含此前未提交改动。基线是最近一次 AIDR 优化之前保存的源码，已包含此前网关、Dify Session、并发回归和 Skill 短事务修复；不是直接使用 HEAD 或更早压测版本。优化版是本轮开始时冻结的工作区。

逐轮源码摘要一致，前后应用文件仅以下三项不同：

- `backend/aidr_models.py`：日志及 Hook 的有效证据关联索引。
- `backend/aidr_migrations.py`：启动时幂等创建索引。
- `backend/aidr_skill_usage.py`：按调用身份批量查询证据、保留来源顺序及独立证据上限；后台每批 50 条、独立提交，每轮最多四批并受 0.5 秒协作预算控制，有剩余工作时缩短等待。

模型网关文件完全相同。源码相同不代表共享资源下的延迟必然相同。证据查询与审计调度作为一个整体比较，本轮没有拆分二者的独立贡献。

沿用 [上一轮混合负载](2026-10-16-skill-audit-transactions.md)：

- 100 个客户端身份、4 路上传、服务端两个采集名额，单 Uvicorn worker、SQLite WAL。
- 每批日志和 Hook 各 10 条，正文 1,024 字节，客户端 outbox 执行 fsync；每第十批故意忽略成功 ACK，按相同字节重传。
- 基准 20 秒、持续采集 30 秒、断网 20 秒、补传与清理 60 秒、恢复 20 秒，之后最多排空 120 秒。
- 低负载日志/Hook 合计生成 100 条/秒，模型/MCP/直连各 1 请求/秒；高负载分别为 400 条/秒、各 5 请求/秒。
- 上游模拟每次 HTTP 调用 50ms，模型非流式、PII 关闭；MCP 保留正常握手流程。
- 十个真实签名的 Registry Skill，每客户端十条初始待审计用量；每 20 个工具调用对附带一次 Skill 文件证据。
- Skill 用量列表和后台概览各 1 请求/秒，走真实管理员认证。列表检查十条种子用量；概览为 `/api/v1/dashboard/overview`，不是 AIDR 概览接口。
- 各类历史数据 10,000 条，使用生产清理代码、预算和后续调度。只将首次清理启动安排在补传窗口。

正式轮次交叉运行，无诊断插桩；pytest 在全部负载结束后执行。新索引启动创建耗时不在请求测量窗口内。本轮没有测量大库首次升级建索引的停顿。

## 环境与统计口径

启动前连续采样 30 秒：CPU 中位数不超过 25%、峰值不超过 35%，可用内存至少 3GiB，实际 Swapins 不超过 30MiB、Swapouts 不超过 10MiB，空闲磁盘至少 22GiB。补传窗口要求 Swapins 不超过 128MiB、Swapouts 不超过 32MiB、可访问外部进程 CPU 中位数不超过 15%、可用内存至少 2GiB。换页来自 `vm_stat`，与 Pageins 分开记录。

正式测试前有三次检查失败，未开始测量；用户保持空闲并退出应用后恢复运行。12 个正式轮次全部通过门槛，无成对数据被剔除。窗口最小可用内存为 3.94GiB，最大实际换入 0.813MiB，换出均为零，外部进程 CPU 中位数范围为 8.33%–10.08%。这是门槛内的共享宿主机测试，不是完全隔离环境。

以下主表取每组 60 秒补传清理窗口的指标，再取三轮中位值；不是合并请求后重新计算 P95。ACK 吞吐是唯一确认记录的增量/窗口时长，包含新增和补传。窗口末积压包含持续新增及 ACK 在途记录。审计待复核含周期复核，不等于首次未认证。审计每两秒采样，页面每种每轮约 60 个 HTTP 请求，不包含浏览器渲染。

## 正确性与回归验证

12 轮总计生成 390,520 条新日志/Hook 记录，4,800 次故意忽略成功 ACK 后重传。每轮日志与 Hook 最终数量分别等于预期；新增 Skill 用量数量也吻合。错误 ACK、剩余 outbox、请求租约、running 网关请求均为零，采集最终全部排空。没有记录到 HTTP/传输、页面认证结果、后台审计或清理错误。三类 AIDR 历史正文及 Pipeline/Runtime Trace 清理核验全部通过。

负载结束后单独执行以下回归测试，**60 passed**，耗时 23.34 秒；记录了 9,482 条弃用警告。结果见本报告关联的结构化结果与原始测试日志：

覆盖真实 HTTP 路径的同批并发重传、冲突回滚、提交失败不返回 ACK、乱序与跨批证据关联、并发新证据/到期保护、审计下一批读取撤销状态、失败批回滚与已提交批保留，以及独立数据库连接间并发名额的原子限制。这些测试支持幂等、并发校验和落盘后 ACK 的保留，不能由无错误压测单独替代。

## 结论、限制与下一步

已确认：本工作负载下审计追赶改善，正确性检查通过；采集吞吐未获得提升，页面和网关尾延迟仍有不利结果。不能宣布全部性能目标通过，也不能把此前单独 SQL 微测的收益比例套用到混合负载吞吐。

合理推测：追赶更频繁使审计更及时，也增加了与采集、页面、网关争用写者和工作线程的机会；新增索引同时带来维护成本。这些可能抵消部分证据查询收益。本轮没有写锁/线程等待插桩，也没有分离索引与调度的因素实验，尚不能确认具体原因或贡献比例。

建议下一步先在独立诊断轮次比较审计、列表、采集和网关的写锁获取、事务持有、线程排队，以及慢请求与清理/追赶批次的时间关系，再决定是否调整审计追赶预算。继续保留已验证语义；本轮证据不构成迁移数据库的必要性结论。

限制：本机模拟 100 个身份，不是真实 100 台 Go 客户端/WAN；未测流式模型、PII、多 worker、大目录旧摘要散列、大分页或浏览器渲染。负载中使用真实签名核对，但未包含独立全量 Skill 扫描。三对样本/负载不能证明生产容量或统计上的严格非劣。

本轮未修改 UI、未新增 UI 单元测试；页面指标只涉及 Skill 用量列表和后台概览 API。浏览器布局及中英文交互验证不在本次压测范围。
