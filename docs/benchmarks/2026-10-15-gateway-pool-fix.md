# 网关连接池等待修复与 100 客户端复跑

本报告比较 [2026-10-14 压测](2026-10-14-aidr-100-clients.md) 中的实现与本次网关修复。数据库继续使用 SQLite WAL，连接池容量保持默认的 5 个连接及 10 个 overflow。测试使用独立临时数据库、合成数据和本地模拟上游。

**结论：同步等待连接池、跨网络等待持有连接的问题已修复并通过针对性回归；高负载下的全局停顿明显改善，历史清理全部完成。但这次改动没有实现网关尾延迟的整体优化：低负载重叠窗口的 P95 反而升高，高负载仍有积压和调用失败，尚不能通过持续容量验收。**

## 最终快照的实测对比

以下“之前”为上次正式压测，“之后”为同一最终修复快照的三档串行复跑。每档均为 100 个模拟客户端；速率和并发条件见后文。未确认数以停止生成并等待最多 120 秒排空后的 outbox 为准。

| 场景 | 之前 ACK / 生成 | 之后 ACK / 生成 | 之后实际入库 | 未确认：之前 → 之后 |
| --- | ---: | ---: | ---: | ---: |
| 400 条/秒，上传并发 100 | 700 / 52,040 | 49,900 / 52,060 | 50,050 | 51,340 → 2,160 |
| 400 条/秒，上传并发 4 | 1,630 / 52,220 | 45,140 / 52,080 | 45,170 | 50,590 → 6,940 |
| 100 条/秒，上传并发 4 | 13,020 / 13,020 | 13,020 / 13,020 | 13,020 | 0 → 0 |

三档接受的 ACK 均通过 durable、摘要及数量检查。低负载日志、Hook 各 6,510 条，故意丢弃 ACK 后重放 200 批仍无重复入库；恢复时 2,010 条积压在 13.61 秒补完，之前为 14.02 秒。高负载虽然完成量显著增加，两档均未在排空期限内清空 outbox。已提交但未确认的记录也在 outbox 内，不能将未确认数称为数据丢失。

### 低负载尾延迟退化的复核

为排除仅由旧基线偏差造成的解释，另外用原来的 203 个应用文件在本机重新跑了同一低负载档。它的网关延迟接近历史基线，最终修复版的退化不能解释成已经改善。

| 补传 + 清理指标 | 历史基线 | 本次重跑旧源码 | 最终修复版 |
| --- | ---: | ---: | ---: |
| 模型 P95 / P99 | 0.970 / 1.174 秒 | 0.962 / 1.548 秒 | 3.954 / 5.939 秒 |
| MCP P95 / P99 | 1.449 / 2.147 秒 | 1.396 / 2.228 秒 | 3.774 / 6.179 秒 |
| 两个网关成功数 | 各 60/60 | 各 60/60 | 各 60/60 |
| 恢复时积压补完 | 14.02 秒 | 13.83 秒 | 13.61 秒 |

最终低负载空载模型/MCP P95 为 160/309 ms；重叠窗口模型中位数为 157 ms、MCP 为 431 ms。慢请求集中在尾部，平均或中位数不足以代表影响。每轮该窗口只有 60 个请求，因此分位数会波动；本报告如实保留最终轮次，不用中间试跑的更好数字替换。

### 清理、事件循环与资源

之前两档高负载均未完成历史清理；修复后三档的预置历史正文及轨迹全部处理完毕，清理任务均无错误。AIDR 保留过期记录的幂等身份，日志、Hook、操作各 10,000 条正文已清理；Pipeline Trace 和 Runtime Trace 历史事件及会话均删除。

| 最终场景 | Pipeline 清理完成 | Runtime Trace 清理完成 | AIDR 清理完成 | 采样到的事件循环最大额外延迟 | Backend 峰值 CPU / RSS |
| --- | ---: | ---: | ---: | ---: | ---: |
| 400 条/秒，上传并发 100 | 37.95 秒 | 58.93 秒 | 54.95 秒 | 374 ms | 219.4% / 251 MiB |
| 400 条/秒，上传并发 4 | 19.29 秒 | 25.33 秒 | 24.83 秒 | 未采到超过 100 ms | 174.6% / 224 MiB |
| 100 条/秒，上传并发 4 | 19.28 秒 | 29.96 秒 | 26.15 秒 | 未采到超过 100 ms | 109.1% / 206 MiB |

完成耗时从该任务首次执行计到首次报告无积压。低负载之前三类清理分别为 11.78、17.33、25.27 秒，修复后并没有全部加快。CPU 以一个逻辑核为 100%；历史两档高负载 CPU 峰值约 114%/109%，完成的工作量也远少于修复后。

之前高负载采样到约 89 秒停顿，最终三轮均未触发 5 秒阻塞栈采样，日志中未出现 QueuePool 超时或 `database is locked`。两档高负载收尾取消未完成上传时，后端有 `ClientDisconnect` 异常日志，不能称为全程无异常。进程退出后只读检查三档 `request_leases` 均为 0。

**已确认**：事件循环不再承担这些同步连接池等待；网络阶段不借用连接的行为由容量为 1 的连接池回归测试验证；完成量和清理完成性改善。**合理推测**：并发数据库阶段之间的写入竞争与调度等待仍影响尾延迟。当前采样没有单独量化写锁、线程排队和各事务耗时，因此尚不能给出各因素占比，也不能据此认定迁移数据库是必要解法。

## 修复范围

- 模型与 MCP 网关的同步鉴权、策略读取、审计及租约申请/释放改在线程中执行。数据库阶段串行使用请求自己的 Session，阶段结束即关闭 Session、归还连接。
- 上游转发和 SSE 输出使用已加载的配置快照，避免事务提交后 ORM 自动刷新重新借出连接。凭证最近使用时间的尽力写入发生回滚时，在工作线程内补齐返回快照。
- 取消请求时等待正在执行的数据库操作退出，再释放租约；模型流式请求在输出期间继续占用并发名额。准备轨迹阶段被取消时也记录中断。
- 日志和 Hook 批量上传鉴权后归还连接，接收完受限请求体后再执行入库事务，保持 durable ACK、摘要校验和幂等规则。
- Runtime Trace 发布统一为先取得进程内轨迹锁，再开始 SQLite 写入，消除模型和 MCP 并发发布时相反的锁顺序。

相关实现为 `backend/services/gateway_db.py`、`backend/routers/llm_gateway.py`、`backend/routers/mcp_gateway.py`、`backend/routers/access_tokens.py`、`backend/routers/aidr.py` 和 `backend/services/runtime_traces.py`。

## 对照条件

三档均为 100 个独立客户端身份。每批 10 条日志或 10 条 Hook，每条正文 1,024 字节；模拟器按既定频率持续生成并 fsync 到 outbox，收到匹配的 durable ACK 才删除，每第 10 批故意忽略一次 ACK 后原样重传。

| 场景 | 日志 + Hook 生成速率 | 每个网关请求率 | 模拟器上传并发上限 |
| --- | ---: | ---: | ---: |
| 高负载 | 400 条/秒 | 5 次/秒 | 100 |
| 高负载、限制上传并发 | 400 条/秒 | 5 次/秒 | 4 |
| 较低负载、限制上传并发 | 100 条/秒 | 1 次/秒 | 4 |

每轮依次运行空载基线 20 秒、持续采集 30 秒、停止上传调度 20 秒、补传与清理 60 秒、继续采集 20 秒；停止生成后最多等待 120 秒排空，期间网关请求继续。断网期间仍生成数据，在途请求可完成。

清理预置日志、Hook、操作各 10,000 条正文，以及 Pipeline Trace 和 Runtime Trace 事件各 10,000 条。复用实际后台清理任务，在补传开始时启动；清理批量上限和调度间隔保持上次设置。模型及 MCP 使用每次 HTTP 延迟 50 ms 的模拟上游，另保留直连上游对照。模型 PII/隐私策略关闭，模型请求为非流式，MCP 保留实际多次 HTTP 握手。

硬件仍为 Apple M1 Pro、10 个逻辑 CPU、16 GiB 内存、macOS arm64；Python 3.12.9、SQLite 3.47.1，单 Uvicorn worker。最终三档复跑与回归测试串行执行，负载生成器、后端及模拟上游共用本机。

## 统计口径与复现

- 成功要求 HTTP 200 且没有协议错误；MCP 的 HTTP 200 中包含 JSON-RPC error 时仍算失败。
- 延迟按请求发起时的阶段归类。结果 JSON 同时保留全部请求延迟、成功请求延迟和计划发送至完成的延迟；失败请求的快速返回不代表性能改善。
- 已入库但尚未确认 ACK 的记录仍留在 outbox。截止排空期限而取消的在途上传计入积压，不进入已完成上传延迟分位；不能将未确认数直接当成丢失数。
- 恢复时已有积压的补完时间与最终 outbox 是否全部排空是不同指标，期间新数据持续生成。
- 事件循环每秒采样，记录额外延迟超过 100 ms 的样本；5 秒无法运行时抓取线程栈。没有记录表示未达到采样阈值，不是精确的零延迟。
- AIDR 清理正文后保留幂等身份和摘要；清理成功不意味着 SQLite 文件立即缩小。
