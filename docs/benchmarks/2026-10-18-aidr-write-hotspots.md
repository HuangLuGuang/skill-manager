# 当前版本 100 客户端混合压测与写锁热点定位

本轮完成 **12 轮正式测试、3 轮独立诊断**。以包含最新页面性能优化和此前回归修复的工作区重新建立基线，定位到 AIDR 到期清理、概览投影的长持锁段，以及采集的大量短写事务。Skill 审计和列表仍受写锁获取等待影响。

**最终应用代码保留本轮开始时的版本。** 一个概览查询构造候选在局部分析中节约 CPU，但正式复测高负载吞吐下降 1.1%、积压增加 8.1%，Skill 列表 P95 在低、高负载下分别上升 32.8%、19.0%。候选已撤回，不能把其模型网关 P95 下降报告为已交付收益。本轮保留诊断分类改进和证据一致性回归测试，之前的功能与性能修复继续保留。

**English:** Twelve formal runs and three separate diagnostic runs establish a fresh mixed-load baseline. AIDR expiry and overview projection hold the writer for comparatively long intervals; ingestion contributes many short transactions. The evaluated query-construction candidate does not meet overall collection/page acceptance and is not retained. Final application sources match the starting snapshot. Diagnostic attribution and evidence-consistency regression coverage remain.

## 条件和对照范围

- 分支 `RENA-1470`，HEAD `eeee22bc312991b64d4c54c8da4fb30c2596a925`，基线为本轮开始时含未提交修改的工作区，不是 HEAD 的干净检出。
- 100 个客户端身份、4 路上传、每批日志/Hook 各 10 条、正文 1,024 字节；本地 outbox fsync，故意忽略每第十个成功 ACK 并按原字节重传。真实 HTTP，单 Uvicorn worker，SQLite WAL。
- 低负载合计 100 条/秒、模型/MCP/直连各 1 请求/秒；高负载 400 条/秒、各 5 请求/秒。模拟上游等待 50ms，非流式，PII 关闭。
- 基准 20s、持续生成 30s、断网 20s、补传与清理 60s、恢复 20s，随后最多排空 120s。每类历史记录 10,000 条，生产清理实现及预算保持不变，只将首次执行安排在补传开始。
- 十个真实签名 Registry Skill、每客户端十条种子用量，每 20 个调用对附带 Skill 证据；Skill 用量列表及后台概览各 1 请求/秒，经过真实管理员认证，保留生产审计和策略核对逻辑。
- 先执行基线六轮（低/高交替），再执行候选六轮（高/低交替），**不是逐轮 A/B 交替**。诊断分别执行，不与正式测量混合。顺序效应尚未排除，三个样本不支持统计显著性或严格非劣结论。
- 候选与基线应用源码仅 `backend/aidr_overview.py` 不同；正式运行不开诊断。最终应用文件逐个 SHA-256 核验与基线相同，模型网关、数据库模型与迁移文件没有本轮变化。

复用原环境门槛：启动前 30 秒 CPU 中位数 ≤25%、峰值 ≤35%，可用内存 ≥3GiB，Swapins ≤30MiB、Swapouts ≤10MiB、磁盘空闲 ≥22GiB；补传窗口外部进程 CPU 中位数 ≤15%、可用内存 ≥2GiB、Swapins ≤128MiB、Swapouts ≤32MiB。换页来自 `vm_stat`，不把 Pageins 当成换入。初始两次启动门槛失败后复查通过才开始测量。

全部正式和诊断轮次通过运行环境检查。正式窗口外部 CPU 中位数为 8.79%–9.83%，最低可用内存 3.57GiB，最大换入 0.313MiB、换出为零。保留 Codex 和网络代理，没有 pytest 与测量并发运行；没有剔除环境合格但性能不利的样本。环境门槛用于排除明显资源干扰；macOS 调度、热状态和时间顺序仍可能波动。

## 已确认的写锁热点

独立诊断在首个隐式 DML 前显式执行 `BEGIN IMMEDIATE`，拆开拿锁与持锁处理，并单独记录物理提交。它会改变调度和开销，**诊断吞吐及页面/网关 P95 不参与上述正式比较**。下表每格是“获取写锁 / 持锁处理 / 物理提交”的 P95，单位 ms；三个不同分布的 P95 不能相加。

| 路径 | 基线诊断 1 | 基线诊断 2 | 候选诊断 1 |
| --- | ---: | ---: | ---: |
| AIDR 清理 | 65.65/130.64/38.10 | 91.56/135.99/40.07 | 66.55/132.40/35.67 |
| 概览投影 | 146.99/147.66/24.92 | 151.49/114.36/27.73 | 272.62/109.24/24.59 |
| Skill 后台审计 | 169.99/21.15/4.01 | 127.84/20.86/12.28 | 150.90/25.94/2.87 |
| Skill 列表 | 125.57/8.20/13.10 | 282.78/5.70/3.30 | 141.12/7.47/14.16 |
| 日志落库 | 100.31/11.88/7.58 | 108.81/11.97/5.64 | 128.06/12.88/6.04 |
| Hook 落库 | 100.15/10.28/5.05 | 95.86/11.18/4.66 | 97.27/11.03/5.45 |

1. **AIDR 到期清理的单事务较长。** 基线两个窗口持锁处理累计均约 4.17s，单次 P95 为 130.64–135.99ms。第一轮记录到的慢 SQL（≥5ms）中，20 次 Hook 清空 UPDATE 累计约 2.024s、线程 CPU 1.996s；20 次操作视图 UPDATE 累计约 1.087s、线程 CPU 1.065s。已确认大量时间花在 SQL 执行，不能全部归因于等磁盘或等锁。索引维护/JSON 表达式分别贡献多少尚未隔离，不能把猜测写成确定根因。
2. **概览投影在写事务内做证据核对和查询构造。** 基线持锁处理累计 4.06/3.85s，P95 为 147.66/114.36ms。局部 cProfile 显示重复构造 UNION 查询及 SQLAlchemy 缓存键存在 CPU 开销。候选仅复用参数化查询结构、每次重新绑定键并读取证据；20×250 操作的隔离 cProfile 从 0.717s 降至 0.339s，而 SQLite execute 自身近似不变。这是带 profiler 的局部实验，不是整体提速 53%。候选诊断投影持锁累计约 3.40s，但获取写锁 P95 升至 272.62ms，整体争用没有稳定改善。
3. **采集事务短但数量多，审计/列表仍在等待写锁。** 基线日志、Hook 持锁 P95 约 10–12ms，而获取写锁约 96–109ms；每窗口两通道合计约 2,700–2,800 次写事务。后台审计持锁约 21ms、拿锁约 128–170ms；列表持锁约 6–8ms、拿锁约 126–283ms。不要用扩大发送并发替代减少持锁工作。
4. **线程池与连接池不是本轮主要等待。** 基线共享线程排队 P95：采集约 1ms、列表约 2.4–3.0ms、概览约 2.9ms；连接池 checkout 通常不足 1ms。Runtime/Pipeline Trace 本身持锁短，仍可能因竞争出现较长拿锁等待。不能根据清理墙钟耗时直接判定它们自身 SQL 最慢。

以上证据定位了等待位置和耗时工作，各路径对尾延迟的独立贡献尚未量化。本轮增强诊断阶段标签，将 AIDR/Runtime/Pipeline/租约清理及概览投影分开；仅 `--diagnostics` 启用，不修改正式负载和生产调度。

## 后续优化边界

优先进一步拆解 AIDR 到期 UPDATE 的执行成本，评估更短清理事务对提交次数、总清理完成时间和补传的净影响；其次测量概览投影中可安全移出写事务的准备工作。任何移出写事务的读取都必须保留提交前并发校验，避免使用过期证据或清理后重建统计。当前证据不支持直接扩大上传/线程并发，也没有证明需要迁移数据库。模型网关继续保持本轮前实现。

这次是单机 100 个模拟身份，不是 100 台真实客户端或 WAN；没有覆盖浏览器渲染、真实全量扫描、PII、流式模型、多 worker 或长期稳态容量。不能从这 3 个正式样本推导生产 SLA 或硬件无关上限。
