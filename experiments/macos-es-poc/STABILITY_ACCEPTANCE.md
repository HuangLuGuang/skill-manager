# macOS 只读观察器：故障与稳定性验收

日期：2026-09-23。GPT-5.6 Sol 子代理实现，主代理独立审查、修正验收条件并运行 sudo 实测。范围为 `experiments/macos-es-poc/`；原有 AUTH 控制源码保持不变。

实测环境：macOS 27.0（26A428）、arm64、Apple M1 Pro、10 个逻辑核、16 GiB 内存。现场 `csrutil status` 确认 SIP disabled，沿用本地 ad-hoc entitlement 签名条件。

阶段结论：故障验收与配置为 1800 秒的持续观察通过。主代理重新解析完整日志、核对二进制哈希及退出后的进程清理；本结论限于下述实测环境与负载。

## 本次实现

- ES 回调只复制必要字段到 8192 条事件队列；消费阶段按到达顺序处理，每条 JSON 使用独立 autorelease pool。
- 日志经 1024 条、每条最大 16 KiB 的有界队列与非阻塞内部管道交给独立 writer 进程。慢输出不阻塞 ES 回调。
- 日志退出给予 2 秒发送/排空时间，必要时终止 writer，再使用最多 500 毫秒回收窗口。缺失 writer 状态、写入失败、超时或丢失均使验收失败。
- 新增 `log_unconfirmed`，区分“未确认最终送达”与“确定丢弃”。它与 dropped 可能重叠，不能简单相加。
- 事件队列溢出时失效旧归属并丢弃当时缓存，避免缓存中的旧 exec 重新建立已经丢失 exit 的身份。单独记录 `event_discarded`。
- 正常可见流完整时退出 0；ES/log 失败退出 74。快照 partial 单独呈现，不等同于 ES 流丢失。
- 注入开关只存在于独立测试构建。正常二进制无运行时注入入口。

## 故障验收结果

真实 ES 原始归档：`evidence/2026-09-23-fault-acceptance/real-es/`，来自 `/private/tmp/macos-es-fault.VfSkZb`。

| 场景 | 独立核验结果 |
| --- | --- |
| 启动缓冲回放 | 104 条真实事件，其中 40 条来自缓存回放；全局及分类型序列连续，8 个探针的 exec/exit 完整身份、root 一致；退出 0 |
| 真实事件队列溢出 | 测试构建容量 4；收到 655 条，拒绝入队 587 条，已入队 68 条，其中处理 4、失效丢弃 64；degraded、退出 74；旧缓存未作为 replay 恢复归属 |
| 序列缺口、重复、乱序 | 使用明确标为 test_injection 的状态机事件验证；旧归属失效，不把模拟序列错误称作实际内核丢事件 |
| 生命周期 | 多次 exec、父退出、PID/pidversion/start time 重用、候选 EXIT/EXEC 失效、重启空状态及容量边界通过 C 回归 |
| ENOSPC | 仅测试构建在 writer 实际 write 调用处返回 ENOSPC，验证错误、未确认数量与失败处理；未填满真实磁盘 |
| writer 异常退出 | idle writer 被终止后，主进程轮询立即检测 status EOF；不会等待最终退出才发现失联 |

测试构建会在快照前短暂等待缓存中已有真实 ES 事件，然后采集快照、回放。此测试证明启动边界的实际缓冲回放，不意味着全部回放事件都发生在 libproc 采样窗口内部。真实事件保持 `source=es_notify`，测试配置单独标记 `test_only=true`。

正常签名二进制的完整输出链路另行实测，归档：`evidence/2026-09-23-fault-acceptance/normal-log-pipes/`。

| 场景 | 结果 |
| --- | --- |
| stdout 管道预先填满且无人读取 | 3.48 秒内退出 74；log_shutdown_timeout=true、未确认 66 条、degraded；无进程组残留 |
| stdout 管道读端断开 | 1.98 秒内退出 74；写入错误明确、degraded；无进程组残留 |
| SIGINT | 快照后发送信号，约 19 毫秒内退出 0，日志排空；无进程组残留 |
| SIGTERM | 快照后发送信号，约 19 毫秒内退出 0，日志排空；无进程组残留 |

信号用例验证的是快照后空闲观察器；满管道用例验证的是输出被阻塞时按运行期限退出。没有把两者写成“所有负载下中断均只需 19 毫秒”。

## 持续观察

最终运行目录：`evidence/2026-09-23-stability-131202-90306/`。

正常二进制 SHA256：`e5a6831e66b1ab6a05d64f7816974c24db507281a3322b8b6fb5b12380cdc63e`。主代理在独立临时目录从最终源码重建并重新签名，哈希与运行中二进制一致；测试宏内的后续修正没有改变正常构建。重建核验记录在 `evidence/2026-09-23-fault-acceptance/reproducible-build.json`。

采样每 5 秒一次，合计观察器及 writer 的进程 CPU 和 RSS；每 30 秒以普通用户执行 `/usr/bin/true`，逐个核对真实 ES 生命周期。CPU 按累计进程时间除以采样时间跨度计算，以一个逻辑核为 100%；RSS 为进程 RSS 之和，共享页可能重复计入。

开始前设置的验收预算：平均 CPU ≤ 单核 5%、合计 RSS 峰值 ≤ 256 MiB；去掉最初一分钟后，末四分位 RSS 中值相对首四分位增量 ≤ 16 MiB。日志文件超过 512 MiB 触发测试停止。短于 1800 秒的运行只报告 smoke_passed，不作为本阶段持续验收。

| 实际运行时间 | 1799.922 秒，约 30 分钟；观察器按整秒截止，符合预设 1 秒容差 |

## 回归、修复与边界

无特权回归：C attribution/state/fault/bounded-log/write-seam 测试通过，实验目录 Python 45/45 通过，zsh 错误/INT 清理回归通过。新增验收器会拒绝错误 root、断裂身份、漏写尾部和伪造的溢出计数。

审查过程中修复了两类测试驱动问题：Objective-C 布尔字段的 JSON 类型错误；zsh 函数错误跳过 EXIT trap、以及清理函数修改 errexit 导致错误后继续输出 PASS。最终驱动使用保存退出码并显式退出的特殊 trap，失败路径和真实驱动均已重新验证。

一次较早的长测在 120 秒时主动中断，以换用已经修复 writer 空闲失联检测的版本。其报告明确为 interrupted，不计作 30 分钟通过。该次退出未强杀且进程组清理完成。

这是本机环境负载加周期探针下的稳定性验收。实际内核丢事件使用序列注入验证处理逻辑；真实溢出验证的是缩小后的同一事件队列。没有据此推断生产吞吐上限、全系统无遗漏或长周期无内存泄漏。stderr 诊断要求普通文件，任意阻塞的 stderr 管道不在当前契约内。

本阶段未启用已有 Agent 会话的阻断，未进行模型请求，未提交、推送或部署。正式签名/SIP 开启环境、跨平台移植及产品服务集成仍为后续工作。
