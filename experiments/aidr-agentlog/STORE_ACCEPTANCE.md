# P1-02 本地状态与崩溃恢复验收

日期：2026-09-23。状态：当前 macOS CLI / Go 存储范围验收通过。
未提交、未推送、未部署；保留已有桌面运行时和其他未提交改动。

## 交付与范围

- `scanner/internal/aidr/localstore/`：专用 SQLite WAL 数据库、原子事件/证据/覆盖/游标提交、独立 outbox、冻结批次、ACK、容量与保留。
- `agent-log-collect` / `agent-log-state`：显式本地采集及状态/事件/批次/历史清理入口。不安装服务，不初始化既有受管客户端库，不联系平台。
- 默认 256 MiB 数据库页配额、100,000 个逻辑 ID、200,000 个证据 ID、200,000 条覆盖历史、4,096 个来源。已 ACK 正文保留 7 天，身份摘要保留用于去重并计入容量；未 ACK 数据不按时间清理。
- 单批上传正文最多 500 条 / 1 MiB。此处 ACK 为本地库接口；真实设备鉴权、平台接收、网络补传尚未实现。
- 环境：macOS 27.0 arm64、Go 1.26.3；Agent 日志版本 Claude Code 2.1.220、Codex 0.155.0-alpha.9.2。

## 自动及进程级故障验收

新增存储包 13 个顶层业务测试（另有强杀子用例及一个子进程 helper）、1 个 CLI 测试。
现有 P1-01 和 runtimeobservation 协议回归一并通过。Go race、vet、本机构建与 Linux/Windows 包交叉编译通过。

| 要求 | 操作与结果 |
| --- | --- |
| 读取后未提交 | 子进程在 after_read 处发出就绪信号，父进程 SIGKILL；重启后 0 条已提交事件，从旧游标重读得到完整 12 条 |
| 事务内部退出 | before_commit 处 SIGKILL；未留下半批事件/游标；重启完整恢复 12 条 |
| 提交后未上传 | after_commit 处 SIGKILL；重启仍有 12 条逻辑事件，续读不增加重复逻辑事件 |
| 接收后未 ACK | 模拟接收端先独立 fsync 持久化批次及记录，再 SIGKILL 客户端；重启返回完全相同批次，重复接收 3 次仍只有 1 个批次、12 条事件和 1 条覆盖记录，匹配 ACK 后推进独立上传序号 |
| 非正常退出可见 | 四种恢复均出现 aidr_store_unclean_shutdown；没有把“可能存在未提交读取”当成已提交事件已丢失 |
| 10,000 条输入 | 分批落库后逻辑/证据数均为 10,000；分页逐一核对预先生成的 call-0…call-9999，无丢失、重复；有界批次全数确认后队列清空 |
| 重复、轮转和时间差 | 同一逻辑调用在不同位置/时间及新文件代次中仅有 1 个逻辑事件，独立证据保留；轮转覆盖仍为 partial |
| 半行与大整数 | 半行跨进程重启后追加换行，完整事件只落库一次；9007199254740993 的偏移重启后值及 JSON 字符串保持精确 |
| 过期提交和内容冲突 | 旧 revision、不同来源事件、相同 ID 不同语义内容、取消事务均拒绝；原事件和游标不被覆盖 |
| 容量拒绝 | 2 条逻辑 ID 配额尝试写 3 条：全部回滚，游标未创建，intake_code 明确报告容量不足 |
| SQLite 页配额 | 实际设为 1 MiB，500 条写入触发 SQLite FULL；返回 aidr_store_capacity，事件数 0，游标未推进，数据库完整性检查 ok |
| 历史淘汰语义 | 未 ACK 正文不删除；只清理已 ACK 且过期正文，保留身份去重；evicted_event_payloads 增加，来源游标和覆盖不变 |
| 独立批次与 ACK | 重新打开数据库后批次字节相同；不匹配摘要拒绝，最近 ACK 重复幂等，读取游标不因 ACK 改变 |
| 来源不可用 | 缺失源无工具事件也保存 unavailable 覆盖；相同空轮询不无限增加 outbox，文件恢复后能继续 |
| 进程和权限 | 同一私有目录第二个写入进程被拒绝；正常关闭后可重新打开；共享权限目录被拒绝 |
| 脱敏 | 合成私密标记不出现在事件查询或数据库/WAL 字节中；源文件内容保持不变 |

强杀测试是真实独立进程的 SIGKILL，不是仅用函数返回值模拟事务失败。
模拟接收端验证的是本地重试协议，不能当作 P1-03 平台接口验收。
页配额测试不是填满用户磁盘，没有进行整盘耗尽、断电或介质故障测试。

## 真实日志与独立 CLI 进程验收

脚本 `verify_store_live.py` 只读已有日志，在忽略目录新建隔离状态库。
先用 P1-01 读取器建立相同来源的参考逻辑 ID 集合，再多次启动 collect 消费，
通过独立 events CLI 分页读取 SQLite 内容并核对集合。P1-01 的原生记录独立核对
见 `ACCEPTANCE.md`；本次主要验证持久化层不会改变其投影。

| 来源 | 参考日志字节 | 采集进程数 | 落库逻辑事件 / 证据 | 待发记录 | 准备批次后数据库文件 |

| Claude | 111,463 | 1 | 16 / 16 | 17 | 155,648 字节 |
| Codex | 27,745,331 | 8 | 1,407 / 1,407 | 1,415 | 6,905,856 字节 |

两种来源的参考逻辑事件及证据 ID 集合均已完整落库、分页无重复、进程关系仍为 unknown；上传序号保持 0。
每种来源用两个独立 CLI 进程 prepare，批次 ID、摘要及正文完全一致。
SQLite `integrity_check` 均为 ok。以上是这次日志快照的数据，活跃 Codex 文件继续增长不改变该次验收范围。

Codex 两条超大 compacted 记录的缺口跨 8 次读取仍被覆盖历史完整保存：
`[13,554,967,18,588,273)` 与 `[21,463,707,26,619,162)`，累计跳过
10,188,761 字节；最终 coverage 保持 partial，不因重新启动或成功落库而变成 complete。

单次真实 Codex 有界采集（4 MiB / 500 事件预算，本次实际 424 条）最大 RSS 为
31,604,736 字节，约 30.1 MiB，包含 Go 与 SQLite；数据库文件 1,941,504 字节。
这是单次负载测量，不是所有数据的峰值承诺。数据库页、记录数、输入和批次有显式
