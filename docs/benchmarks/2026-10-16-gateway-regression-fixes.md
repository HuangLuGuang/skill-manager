# 性能改动三处回归修复与 100 客户端复测

三处功能回归已修复，最终受影响测试 85 项通过。14 轮最终源码的同参数对照全部完成落盘、幂等重传、租约和清理完整性检查。低负载修复版模型 P95 保持在 258.24–270.63 ms，但高负载存在吞吐下降和积压增加，本轮不能确认整体性能不回退。主机 CPU 与页面调入活动明显波动，历史采样未单独记录交换区读写，数据不足以将差异全部归因于代码或环境。

## 修复范围与语义

- AIDR：对可被迟到结果刷新的操作视图，在 UPDATE 时重新检查完整到期条件，避免选择旧记录后误清掉已经落盘并 ACK 的新结果。保留原始事件幂等身份、哈希和批次回执。实际清理数量与是否用满候选批次分别计算；满批候选全部被刷新时仍短间隔继续处理剩余记录。
- 模型网关：正常请求仍将 Runtime Trace、会话完成及租约释放合并提交；可选 Trace 事务失败回滚后，独立完成请求状态及会话指纹，租约由已有退出路径释放。审计及用量保持独立持久化。若会话数据库操作本身持续失败，本次修复不能保证状态落盘。
- MCP 扫描：网关释放数据库连接使 ORM 对象脱离 Session 后，扫描调用先重新关联对象再读取状态并结束记录。早期拒绝保留原 HTTP 错误并写入 failed；重复 call_id 仍拒绝，上游不会被错误调用。

数据库仍为 SQLite；幂等、授权、并发租约、落盘后 ACK 和正常路径的批次事务边界保持。相对上一轮已优化版本仅修改三个应用文件：`backend/aidr_retention.py`、`backend/routers/llm_gateway.py`、`backend/services/mcp_scan_control.py`。

## 到期校验的查询计划

直接追加到期范围条件会使 SQLite 改用 `ix_aidr_operations_retention`，在每批 UPDATE 中扫描已选 500 个主键之外的到期范围。最终使用 CASE 表达完整资格条件，使更新保持 `SEARCH aidr_operations USING INTEGER PRIMARY KEY`；真实表结构和生成 SQL 的回归测试固定了该要求。

与压测相同的 SQLite 3.47.1、10,000 条内存样本、每次更新 500 条、每种方案交错 30 次：未校验版本/范围条件版本/最终 CASE 版本的线程 CPU 中位数分别为 1.121/3.024/1.533 ms。最终版本保留必要校验的开销，消除了额外范围扫描。这是简化表结构的内存微基准，不含提交/fsync、混合锁等待或生产磁盘，不能用它解释全部网关 P95 差异。

三组低负载、两组高负载 4 路、两组高负载 100 路，共七对。按低负载后/前、前/后、后/前，高负载 4 路前/后、后/前，高负载 100 路后/前、前/后的顺序串行运行；未并行执行测试或微基准，正式轮关闭诊断插桩。每轮开始前检查磁盘可用空间超过 20 GiB，完成核验和证据归档后删除本轮临时数据库。第 12 轮结束后，可用空间降至约 19.78 GiB，门槛阻止下一轮启动；空间恢复到约 24 GiB 后从检查点继续最后两轮，已完成数据未被替换。这是测量间暂停，未发生测量中磁盘耗尽。

网关 P95 统计补传清理窗口发起的成功请求；低负载每网关每轮约 60 个、高负载约 300 个样本。ACK 吞吐为该窗口唯一持久化 ACK 增量除以实际墙钟时间，包含断网积压，不能作为持续容量。未确认量可能包含已提交但 ACK 在途的记录。

## 回归测试与完整性

最终受影响测试集 85 项通过，包含迟到结果在清理 SELECT/UPDATE 之间完成落盘 ACK 的真实交错、过期事件重传幂等、满批刷新后的继续清理、实际 SQL 查询计划、可选 Trace/提交失败后的会话及指纹、早期 MCP 拒绝及重复 call_id。已有并发租约、取消和 ACK 时序检查一并覆盖。

较大相关测试集在最终 CASE/清理预算调整前执行：837 passed、3 failed、5 skipped；随后以最终源码重跑上述受影响 85 项，不能把两次通过数量相加。三个失败均在此前独立 HEAD 快照复现：Hook bridge 的 `KeyError: command`，以及两个 token 测试替身不接受 `include_scan_report` 参数。它们不属于本次新增回归，但整个较大测试集并非全绿。

14 轮最终日志和 Hook 数量均等于生成预期，最终未确认、残余 outbox、错误 ACK、残余请求租约及 running 网关请求均为零。每轮日志、Hook、操作各 10,000 条到期正文清空，Pipeline Trace 与 Runtime Trace 事件/会话清理完成，无清理任务错误。全部阶段的采集、模型、MCP 和直连请求未记录 HTTP 或传输错误。

模拟使用 100 个身份而非 100 个原生 Go 进程，断网为暂停发送而非真实网络中断。真实 WAN、原生客户端 10 s 超时、流式请求、PII、多 worker 和生产磁盘尚未在这次验证；驱动请求超时为 35 s。未修改 UI、未迁移数据库、未部署。
